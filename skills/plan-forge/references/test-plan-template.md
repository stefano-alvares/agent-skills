# Test plan section

Write this as the `## Test plan` section of the eng-review file. `qa` reads it as its primary scope, so it says **what to test and where**, not how to implement it. Update it when a later answer changes the requirements.

```markdown
## Test plan
Generated by plan-forge (high-risk review) on <date> · target <plan path> · <branch> @ <short sha>

### Affected routes and commands
- <route or command> — <what to test and why>

### Key interactions to verify
- <interaction> on <route>, at <1440 | 390 | both>

### Edge cases
- <edge case> on <route>
  Value: protects=<...>; fails_when=<...>; why_new=<...>; seam=none; no_claim=<...>

### Critical paths
- <end-to-end flow that must work>
  Value: protects=<...>; fails_when=<...>; why_new=<...>; seam=none; no_claim=<...>

### Checkable rules from decided.md and the acceptance file
- <rule> — <how qa checks it>

### Tests to retire
- <existing test made obsolete and why, or none>

### Pending decisions
- <test requirement waiting on ledger entry Dn, or none>
```

## Value card

`Value: protects=<behaviour or contract>; fails_when=<credible regression>; why_new=<why existing coverage misses it>; seam=<none or its name>; no_claim=<what green does not prove, and which mocks stand in for what>`

Example: `Value: protects=add-to-bag works with JavaScript off; fails_when=the form posts to a client-only handler; why_new=cart.test.ts covers the JS path only; seam=none; no_claim=payment provider acceptance (mocked; unit only)`

Rejected example: "home page renders" — `home.e2e.ts:9` covers it, so extend that test instead.

Only approved requirements go under Edge cases and Critical paths; anything waiting on an answer goes under Pending decisions.
